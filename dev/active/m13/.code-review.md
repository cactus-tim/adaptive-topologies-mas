## Findings

### Finding 1 — Notebook loader cells use `dsn=` kwarg that does not exist on loaders
- **Severity**: critical
- **File**: `scripts/gen_analysis_notebook.py:102-113`
- **Reference**: Plan Step 10.1 — "Acceptance: 4 tests green"; loader contract Step 3.1/5.1 — loaders accept `session_factory` not `dsn`
- **Issue**: Every async loader cell in `_setup_cells()` calls the loaders with `dsn=PG_DSN`, e.g. `load_experiment(EXPERIMENT_ID, dsn=PG_DSN)`, but all six async loaders in `loaders.py` accept `session_factory: Any` as their keyword argument. There is no `dsn` parameter on any loader.
- **Expected**: Cells should pass a `session_factory` (or document how to construct one from a DSN). No loader has a `dsn` parameter.
- **Actual**: `load_experiment(EXPERIMENT_ID, dsn=PG_DSN)` — would raise `TypeError: load_experiment() got an unexpected keyword argument 'dsn'` at runtime.
- **Suggested Fix**: Either (a) add a `dsn: str | None = None` parameter to the async loaders that constructs a `create_async_engine` + `async_sessionmaker` internally when `dsn` is provided and `session_factory` is None, or (b) update the notebook cells to show how to build a `session_factory` from a DSN and pass that instead. Option (b) keeps the API simpler; a helper utility `session_factory_from_dsn(dsn)` could be added to `loaders.py`.

### Finding 2 — Notebook `load_oracle_table()` called with no arguments
- **Severity**: critical
- **File**: `scripts/gen_analysis_notebook.py:118`
- **Reference**: `oracle.py:364` — `def load_oracle_table(path: Path | str) -> OracleTable`
- **Issue**: The notebook setup cell contains `oracle = load_oracle_table()` with no arguments. The function signature requires a mandatory positional `path` argument.

- **Actual**: `load_oracle_table()` — would raise `TypeError: load_oracle_table() missing 1 required positional argument: 'path'`.
- **Suggested Fix**: Change the cell to `oracle = load_oracle_table("conf/oracle/type_level_manual.yaml")` (or use a variable like `ORACLE_PATH` defined in the config cell).

### Finding 3 — Notebook `compute_hurt_rate` receives wrong column name

### Finding 4 — Notebook `plot_transition_timeline_quality` receives positional second argument that is a keyword-only parameter
- **Severity**: critical
- **File**: `scripts/gen_analysis_notebook.py:204`
- **Reference**: `plots.py:310-314` — `def plot_transition_timeline_quality(transitions_df, *, run_id: str, ...)`
- **Issue**: The notebook calls `plot_transition_timeline_quality(transitions_df, runs_df)`. The function signature is `(transitions_df, *, run_id: str)` — `run_id` is keyword-only (after `*`). `runs_df` cannot be passed as the second positional argument.
- **Expected**: The function requires `run_id=<str>` as a keyword argument, e.g. `plot_transition_timeline_quality(transitions_df, run_id=runs_df["id"].iloc[0])`.
- **Actual**: `plot_transition_timeline_quality(transitions_df, runs_df)` — would raise `TypeError: plot_transition_timeline_quality() takes 1 positional argument but 2 were given`.
- **Suggested Fix**: Update the notebook cell to pick a specific `run_id` string: e.g. `run_id = runs_df["id"].iloc[0]` then `plot_transition_timeline_quality(transitions_df, run_id=run_id)`.

### Finding 5 — Notebook `plot_router_cost_share` called with wrong arguments
- **Severity**: critical
- **File**: `scripts/gen_analysis_notebook.py:214`
- **Reference**: `plots.py:448-452` — `def plot_router_cost_share(runs_df, llm_calls_df, *)`
- **Issue**: The notebook calls `plot_router_cost_share(transitions_df, runs_df)` but the function expects `(runs_df, llm_calls_df)`. `transitions_df` does not have a `cost_usd` column; `runs_df` is not `llm_calls_df`.
- **Expected**: `plot_router_cost_share(runs_df, llm_df)` where `llm_df` is the LLM calls DataFrame loaded by `load_llm_calls_for_experiment`.
- **Actual**: The guard `if llm_calls_df.empty or "cost_usd" not in llm_calls_df.columns` would silently return an empty figure (since `runs_df` has no `cost_usd` column), masking the bug but producing a wrong plot.
- **Suggested Fix**: Change the notebook cell to `plot_router_cost_share(runs_df, llm_df)`.

### Finding 6 — `compute_guard_override_rate` formula deviates from experiment_plan.md §4
- **Severity**: major
- **File**: `src/atm/analysis/metrics.py:60`
- **Reference**: `arch/experiment_plan.md` line 125: `guard_override_rate = |guards_applied > 0| / всего decisions`
- **Issue**: The plan defines `guard_override_rate` as the fraction of decisions where `guards_applied` is non-empty (i.e., at least one guard fired). The implementation instead counts rows where `decided_by == "guard_override"`. These two metrics differ: a guard may have been applied (present in `guards_applied`) without the final decision being classified as `"guard_override"` by the `decided_by` field.
- **Expected**: Formula should be: `(transitions_df["guards_applied"].apply(lambda x: len(x) > 0 if x else False)).sum() / len(transitions_df)`.
- **Actual**: `(transitions_df["decided_by"] == "guard_override").sum() / len(transitions_df)`.
- **Suggested Fix**: Change the implementation to count rows where `guards_applied` is a non-empty list/array. The `decided_by` approach is a valid but different metric (strict override). The docstring currently documents the `decided_by` formula, not the plan's `guards_applied` formula — one of the two should be authoritative. If `decided_by == "guard_override"` is the intended semantics, update the experiment_plan.md §4 reference in the docstring.

### Finding 7 — `plot_phase_timeline` default `phase_col="phase"` does not match `load_phases` column output `phase_name`
- **Severity**: major
- **File**: `src/atm/analysis/plots.py:223` / `src/atm/analysis/loaders.py:392`
- **Reference**: Plan Step 5.1 acceptance: "column sets match"; Step 7.1 acceptance: "plot_phase_timeline smoke test green"
- **Issue**: `load_phases` (PG path) returns a DataFrame with column `phase_name` (loaders.py line 392). `plot_phase_timeline` defaults to `phase_col="phase"`. A caller using the loader's output with the plot function without overriding `phase_col` will hit the "missing columns" guard and receive an empty figure with a warning title.
- **Expected**: Either `load_phases` should return a `phase` column, or `plot_phase_timeline` should default to `phase_col="phase_name"` to match the loader output. The notebook template does not pass `phase_col`, so it would silently show an empty figure.
- **Actual**: `phases_df` from `load_phases` has `phase_name`; `plot_phase_timeline(phases_df, run_id=...)` looks for `"phase"` → missing → graceful fallback, wrong output.
- **Suggested Fix**: Change `plot_phase_timeline` default from `phase_col: str = "phase"` to `phase_col: str = "phase_name"` to match the loader contract. Update the docstring accordingly.

### Finding 8 — Notebook `compute_time_per_topology` called with `phases_df` instead of `transitions_df`
- **Severity**: major
- **File**: `scripts/gen_analysis_notebook.py:199`
- **Reference**: `metrics.py:119` — function docstring: "DataFrame with columns `run_id`, `to_topology`, and `at`"
- **Issue**: The notebook calls `compute_time_per_topology(phases_df)` but the function expects a `transitions_df` with `to_topology` and `at` columns. `phases_df` does not have `to_topology`; the function will return `{}` (empty dict) because no valid `to_topology` is present.
- **Expected**: `compute_time_per_topology(transitions_df)`.
- **Actual**: `compute_time_per_topology(phases_df)` — silently returns empty dict. The notebook also calls `plot_time_per_topology(phases_df)` which would succeed via the fallback count-by-topology path only if `phases_df` has a topology column — it does not, so that will also return an empty figure.
- **Suggested Fix**: Change both calls to use `transitions_df`. Update the notebook RQ2 cell at line 199 to `compute_time_per_topology(transitions_df)` and at line 219 to `plot_time_per_topology(transitions_df)`.
