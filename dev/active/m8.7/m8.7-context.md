## Decisions

**OracleTable JSON shape must match `OracleTopologyRouter` exactly**
- Decision: `default_topology` field uses `alias="_default"` and `serialization_alias="_default"` so `to_json_dict()` emits `"_default"` (not `"default_topology"`). Use `model_config = ConfigDict(frozen=True, populate_by_name=True)`.
- Rationale: `OracleTopologyRouter` reads JSON with key `"_default"`. The existing fixture `tests/fixtures/oracle_table.json` demonstrates this shape and we must reproduce it exactly.

**LOO pure/async split**
- Decision: `_build_loo_from_rows(rows, exp_id) -> OracleTable` is a pure synchronous function; `build_leave_one_out_oracle()` is an async thin wrapper that queries DB and delegates.
- Rationale: Pure helper is testable without a DB using `@dataclass FakeRun`; keeps integration surface minimal.

**`task_type` inference via prefix (no DB column)**
- Decision: `_infer_task_type(task_id: str) -> str` maps prefixes: `"HumanEval/"` -> `"programming"`, `"gsm8k/"` -> `"reasoning"`, `"commongen/"` -> `"creative"`, `"dabench/"` -> `"decision"`, all others -> `"unknown"`. Case-sensitive (lowercase `"humaneval/"` -> `"unknown"`).
- Rationale: `runs` table has no `task_type` column; prefix mapping is deterministic and matches task-loader formats in `src/atm/tasks/`.

**Per-phase granularity: same topology for all phases**
- Decision: LOO oracle emits the same best topology for `planning`, `execution`, and `verification` phase keys. True per-phase analysis requires joining `topology_transitions` and is out of scope.
- Rationale: `runs.topology` covers the full run, not individual phases. Per-phase manual overrides are the responsibility of `conf/oracle/type_level_manual.yaml`.

**Tie-break ordering**
- Decision: `(-mean_quality, mean_cost_usd, mean_wall_s, topology_name_lex)` — primary descending quality, then ascending cost, then ascending wall time, then lexicographic topology name as final deterministic tiebreak.
- Rationale: Consistent determinism required for reproducible oracle generation across runs.

**`by_task_id` LOO fallback behavior for single-task experiments**
- Decision: When LOO remainder is empty (all rows belong to the target task_id), omit the `by_task_id` entry entirely. Consumer falls through to `by_task_type` then `_default`.
- Rationale: Emitting a vacuous entry would mislead consumers. Documented in `OracleTable` docstring.

**Integration test skip mechanism**
- Decision: Use `session_factory_fast` fixture — skip is inherited transitively from `pg_dsn` fixture which calls `pytest.skip()` when `ATM_INTEGRATION_PG != "1"`. Do NOT add a manual `pytest.skipif`.
- Rationale: Pre-existing pattern in the test suite; avoids redundant skip logic. The `requires_postgres` marker is for pytest selection only.

**`state["task_type"]` must be seeded explicitly in tests**
- Decision: All tests exercising the `by_task_type` fallback must populate `state["task_type"]` manually.
- Rationale: `OracleTopologyRouter.decide()` line 392 is a `pass` stub — the router does NOT auto-infer `task_type` from `task_id`. This is intentionally out of scope for M8.7.
