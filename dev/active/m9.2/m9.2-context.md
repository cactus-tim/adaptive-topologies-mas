## Архитектурные решения

**Решение: Alt-A — финальная роль из БД, не из SharedState**
- Что: `runs.human_role` обновляется через `SELECT role FROM human_interactions WHERE run_id=? ORDER BY requested_at DESC LIMIT 1` в `_update_run_success`, а не через запись в `SharedState`.
- Почему: `SharedState` — closed TypedDict, добавление нового ключа потребовало бы изменения `SharedState` + `_build_initial_state`. SQL-запрос устраняет C1 полностью и попутно фолдится в тот же блок финализации, что и `cognitive_load_proxy`.

**Решение: `_build_role_router` возвращает `None` для `role_router="fixed"`**
- Что: вместо `FixedRoleRouter(cfg.human.role)` фабрика возвращает `None`.
- Почему: топологии делают `if role_router is not None: ... else: active_role = human_cfg.role` — path через `None` полностью идентичен pre-m9.2 поведению, без дополнительных вызовов.

**Решение: `sa.Float()` вместо `sa.Double()`**
- Что: колонка `cognitive_load_proxy` объявлена как `FLOAT NULL`.
- Почему: `sa.Double()` маппится в `DOUBLE PRECISION` и не портабельно на всех SQLite-сборках, используемых в юнит-тестах (фикс M6).

**Решение: Debate `_both_judge_postprocess` — outer closure capture**
- Что: `role_router` захватывается в теле `build(self, ..., role_router=None, **kwargs)`, доступен всем вложенным closures включая `_both_judge_postprocess`.
- Почему: standalone-функция с новым аргументом нарушила бы контракт компилируемого subgraph'а (фикс C3).

**Решение: `context_len` = `len(json.dumps(context_json))` (byte-size)**
- Что: для метрики β-компонента используем размер сериализованного JSON-контекста в байтах.
- Почему: наиболее простой и стабильный proxy; не зависит от структуры context_json.

## Ограничения и invariants

- **Back-compat обязателен**: при `role_router="fixed"` (default) все 6 топологий должны вести себя байт-идентично m9.1 — никаких новых вызовов, никаких новых событий.
- **`SharedState` TypedDict не модифицируется** — Alt-A устраняет эту необходимость.
- **`_update_run_failed` не получает доп. логику** — budget-failed runs имеют NULL в `human_role` и `cognitive_load_proxy`; аналитический pipeline E4 должен это учитывать (документировано, фикс M3).
- **Оба блока финализации (`last_role` + `cog_proxy`) обёрнуты в `try/except Exception`** — failure в БД не блокирует `_update_run_success` (фикс M2).
- **`HumanCfg.role` остаётся initial/fallback** — новые поля имеют дефолты, не ломающие существующие YAML-конфиги.
- **FakeLLM фикстура Star** (`m9_2_star_role_router.yaml`) должна детерминированно довести run до verification-фазы для получения ≥2 разных ролей.
