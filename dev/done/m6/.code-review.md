### Verified blocking fixes

#### SEC-1: DSN redacted in traceback before storage (RESOLVED)
- **File**: `src/atm/experiment/runner.py:122-152, 701`
- **Evidence**: `_redact_dsn(text, dsn)` helper introduced at line 122. It
  uses `urllib.parse.urlparse` to extract `parsed.password` and replace
  `:{password}@` with `:***@`; a fallback replaces the full DSN literal
  with `<redacted-dsn>`; a defence-in-depth regex
  `r"(postgresql(?:\+\w+)?://[^:]+):[^@]+(@)"` catches residual matches.
  Invocation at line 701:
  `error_text = _redact_dsn(traceback.format_exc(), pg_dsn)` before the
  text is written to `runs.error_text` (line 720, truncated to 2000 chars).
- **Residual risk**: `log.error("run failed", error=str(exc))` at line 698
  may still emit the DSN if the exception message itself contains it
  (e.g. SQLAlchemy connection errors echo the URL). This is a separate
  log-surface concern not called out by SEC-1 and is out of scope.
  Recommend addressing in a follow-up.

#### SEC-2: Fixture path traversal validation (RESOLVED)
- **File**: `src/atm/experiment/runner.py:155-181, 402`
- **Evidence**: `_resolve_fixture_path(fixture_str)` helper introduced at
  line 155 raises `ValueError` for absolute paths
  (`p.is_absolute()`) and for any component containing `".."`
  (`".." in p.parts`). Invocation at line 402 replaces the previous
  unchecked `Path(fixture_str)`:
  `fixture_path = _resolve_fixture_path(fixture_str) if fixture_str else None`.
  The `ValueError` propagates into the generic `except Exception` branch
  which flushes parquet and marks the run failed with a redacted error —
  correct failure semantics.

#### CR-MAJOR-1: Chain router no longer mutates state (RESOLVED)
- **File**: `src/atm/topology/chain.py:100-102, 158-190`
- **Evidence**: Counter increments moved into `_critic_postprocess`
  (lines 100-102:
  `shared["iter_total"] = shared.get("iter_total", 0) + 1` and the same
  for `iteration`). `_route_from_critic` is now a pure read-only router
  (docstring explicitly states "This is a pure read-only router …
  Counters are incremented in `_critic_postprocess`"). The previous
  in-place `shared["iter_total"] += 1` inside the router is gone.
  Unit tests confirm both halves of the invariant:
  `TestCriticPostprocessCounters::test_increments_iter_total` /
  `test_increments_iteration` / `test_increments_from_zero` assert the
  node-side delta; `TestRouteFromCritic::test_does_not_mutate_iter_total`
  / `test_does_not_mutate_iteration` assert the router's purity.

#### CR-MAJOR-2: Chain `final_answer` invariant on all terminal paths (RESOLVED)
- **File**: `src/atm/topology/chain.py:128-148`
- **Evidence**: The conditional `if approved:` guard around the DRAFT
  extraction is gone. The new unconditional block extracts the last
  executor DRAFT on every invocation and defaults to `"<incomplete>"`
  if none exists. `final_answer: str` is declared with a non-Optional
  annotation (line 143), and the returned delta always contains
  `shared["final_answer"]` as a `str`. Test
  `test_rejected_sets_final_answer_incomplete` directly asserts
  `final_answer == "<incomplete>"` on the rejected path;
  `test_rejected_sets_final_answer_from_last_draft` asserts the
  partial-DRAFT path on rejection.

#### CR-MAJOR-3: CLI exit-1 path reachable and covered (RESOLVED)
- **File**: `src/atm/experiment/cli.py:47-54`, `tests/unit/experiment/test_cli.py:135-154`
- **Evidence**: `asyncio.run(run_one(cfg))` is now wrapped in
  `try: ... except Exception as exc: typer.echo(f"Run failed: {exc}",
  err=True); raise typer.Exit(1) from exc`. The test
  `test_failed_run_exits_1` has been updated: `fake_run_one_raises`
  `raise RuntimeError("simulated run failure")` replaces the previous
  `return RunResult(status="failed")`, so the test now exercises the
  real re-raise path from `run_one` and verifies the CLI translates it
  to exit 1. `result.exit_code == 1` holds under the new semantics.
