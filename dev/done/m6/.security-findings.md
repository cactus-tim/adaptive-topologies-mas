## Findings

### 1. CRITICAL: Sensitive Data Exposure in Error Tracebacks

**File:** `src/atm/experiment/runner.py:641`
**Line:** 641
**Severity:** CRITICAL
**Description:**

The `pg_dsn` (PostgreSQL connection string) is captured in the function scope and can be exposed in error tracebacks. When an unhandled exception occurs after `pg_dsn` is assigned (lines 457-461), the traceback captured at line 641 will include the full stack trace, which may contain the DSN variable with its password in frame locals.

```python
pg_dsn = cfg.observability.pg_dsn  # Line 457
# ... later ...
except Exception as exc:
    error_text = traceback.format_exc()  # Line 641 — includes frame locals with pg_dsn
```

If database connection fails (e.g., connection refused, authentication failure, timeout during `create_engine()` or schema creation), the traceback will expose the full PostgreSQL DSN including username and password to:
- The database error field (line 660: `error=error_text[:2000]`)
- Application logs (line 638: `log.error("run failed", error=str(exc))`)

**Impact:**
- Database credentials leaked to application logs and PostgreSQL error log table
- Compromised database access if logs are exposed

**Remediation:**
Use `traceback.format_exc(chain=True)` with exception context scrubbing, or capture only the exception message and type without the full traceback. Alternatively, mask sensitive DSN data in tracebacks before storing.

### 2. HIGH: Unsafe Fixture Path Resolution Without Validation

**File:** `src/atm/experiment/runner.py:334-342`
**Lines:** 334-342
**Severity:** HIGH
**Description:**

Fixture paths from user-provided config are converted to Path objects without validation for path traversal or absolute path escapes:

```python
fixture_str = cfg.model.fake_fixtures.get(role)  # User-controlled via YAML config
fixture_path = Path(fixture_str) if fixture_str else None
```

Although test fixtures are expected to be in `tests/fixtures/llm/`, there is no runtime validation to prevent:
- `../../../etc/passwd`
- `/etc/passwd`
- Symlink escape attacks

**Impact:**
- Low in current scope (test fixtures only, trusted config in dev/CI)
- High if `--config` parameter is exposed to untrusted users in production

**Remediation:**
For test fixtures, add validation:
```python
if fixture_str:
    fixture_path = Path(fixture_str)
    # Prevent absolute paths and traversal
    if fixture_path.is_absolute() or ".." in fixture_path.parts:
        raise ValueError(f"Invalid fixture path: {fixture_str}")
```

## Recommendations

**Immediate (Critical):**
1. Add exception handling to mask DSN in tracebacks before storing to DB
   - Catch exceptions at `create_engine()` and schema creation with custom error handling
   - Or use a custom logging filter to redact DSN from traceback strings

**Short-term (High):**
2. Add fixture path validation in `_build_llm_wrappers()`
   - Prevent absolute paths and `..` traversal
   - Validate fixtures exist before passing to FakeLLM

**Future (Low Risk):**
3. Consider separating credential handling from main run_one logic for better testability
4. Add integration tests that verify tracebacks do not expose DSN
