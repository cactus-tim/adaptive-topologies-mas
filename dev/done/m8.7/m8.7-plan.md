# M8.7 Oracle Labels Pipeline — Plan

## Executive Summary

Implement the Oracle labels pipeline that produces an `OracleTable` consumable by `OracleTopologyRouter` (M8.3) and by the M13 G9 LOO-plot analysis. The module lives in `src/atm/analysis/oracle.py` and exposes three public callables: `build_leave_one_out_oracle()` (async, Postgres-backed), `load_oracle_table()` (sync, json/yaml), and the `OracleTable` Pydantic model with `to_json_dict()` / `from_json_dict()`. A manual YAML skeleton in `conf/oracle/type_level_manual.yaml` serves as a human-fillable type-level override template.

## Current State

- `src/atm/analysis/__init__.py` exists but is empty (1-line whitespace).
- `OracleTopologyRouter` in `src/atm/phases/topology_router.py` already reads a JSON oracle but has no pipeline to produce one.
- `tests/fixtures/oracle_table.json` demonstrates the required JSON shape.
- `conf/oracle/` directory does not yet exist.
- No unit or integration tests exist for the analysis layer.

## Proposed Approach

TDD in two waves. First write failing unit tests that lock the `OracleTable` contract and LOO algorithm (including a non-tautology guard that forces the exclusion step to actually flip the winner). Then implement `oracle.py` to make those tests pass. A separate integration test round-trips through real Postgres and through `OracleTopologyRouter` to confirm the producer/consumer schema contract holds. Manual YAML skeleton can be authored in parallel since it requires no code.

Key design decisions:
- `OracleTable` is a frozen Pydantic v2 model. The `default_topology` field uses `alias="_default"` so `to_json_dict()` emits the `"_default"` key that `OracleTopologyRouter` expects.
- The LOO algorithm is split into a pure helper `_build_loo_from_rows()` (testable without a DB) and a thin async wrapper `build_leave_one_out_oracle()` that opens a session and delegates.
- `task_type` is derived at runtime from `task_id` prefix via `_infer_task_type()` because the `runs` table has no `task_type` column.
- Per-phase granularity: a single `Run` row covers all phases under one topology. M8.7 emits the same best topology for all three phase keys (`planning`, `execution`, `verification`). True per-phase LOO requires joining `topology_transitions` and is out of scope.

## Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Pydantic `_default` alias (leading underscore) breaks model introspection | Medium | High | Use `Field(alias="_default", serialization_alias="_default")` + `ConfigDict(populate_by_name=True)`; verified in Pydantic 2.6+ |

| `budget_spent_usd` Decimal precision loss in float aggregation | Low | Low | Acceptable for secondary tie-break; primary sort key is `quality_score` |
| Integration test inserts missing NOT NULL fields on `Run` | Medium | Medium | Reference `tests/integration/storage/test_smoke_run.py:94-117` insert pattern; fill all NOT NULL fields explicitly |
| `state["task_type"]` not seeded in tests; router falls through to `_default` silently | Medium | Medium | All tests that exercise `by_task_type` fallback must populate `state["task_type"]` — documented in both plan and test comments |
