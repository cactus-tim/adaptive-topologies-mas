# M9.1 — HITL integration в остальные 5 топологий — Plan

## Executive Summary

Расширить HITL-инфраструктуру, поставленную в M9 (HumanGateway Protocol, LLMSimulatedGateway, CLIGateway, `request_with_timeout`, idempotency через UNIQUE-constraint + callback writer, `human_gateway_llm` wiring в Runner), на остальные 5 топологий: **Star / Mesh / Debate / Hierarchical / Adaptive**. M9 реализовал интеграцию только в Chain как reference-implementation. M9.1 — graph-wiring per topology + per-topology unit + integration тесты.

Default-режим (без `human_cfg.enabled=True`) каждой топологии должен оставаться **байт-в-байт идентичен** поведению до M9.1 — это explicit exit criterion.

Дополнительно: заполнить `runs.human_role` в Runner (поле уже в SQLAlchemy-модели с M3, но никем не пишется).

**Final Class**: complex

## Current State

- M9 инфраструктура полностью готова и протестирована; Chain — единственная топология с HITL.
- `runs.human_role` объявлен в `storage/models.py:138` как `String(32), nullable=True`, но нигде не пишется.
- `TopologyDecision.decided_by` и `TopologyTransition.decided_by` — Literal без `"human_override"` → Pydantic ValidationError при попытке записать это значение.
- `HumanCfg` не имеет поля `extra` — нет способа передать per-topology настройки (judge mode, scope, override flags, activation_round).
- Star, Mesh, Debate, Hierarchical, Adaptive — HITL-узлы отсутствуют.

## Proposed Approach

### Архитектурные решения

**1. `HumanCfg.extra: dict[str, Any] | None = None`** — backwards-compatible extension для per-topology kwargs. Caller responsibility для key naming. Альтернатива (конкретные поля) отклонена в пользу минимальных изменений config.py. Weakness: typos pass silently (GAP-2, advisory).

**2. `build_human_node_factory` helper** (`src/atm/human/_node_factory.py`) — экстракция canonical HITL-node pattern из Chain для переиспользования в Star/Mesh. Debate/Hierarchical/Adaptive используют собственные inline closures (специфичная семантика).

**3. Debate "both" mode — sequential composite** (не parallel). Одна closure `_both_judge_postprocess`: (1) LLM-judge inline, (2) human gateway, (3) aggregate human > critic. Acceptable: human latency >> LLM latency; parallelism не нужен.

**4. Hierarchical sub_team mode — no interrupt** внутри subgraph. CLIGateway внутри subgraph — known limitation M9.1, `WARNING` docstring, deferred to M9.2. M9.1 покрывает только LLMSimulatedGateway path (synchronous).

**5. Adaptive default — advisory** (не override). `HumanCfg.extra["human_can_override_router"]=True` включает override-режим. Advisory mode: human-hint в `signals`, routing не меняется. Override mode: `TopologyDecision` и `TopologyTransition` перезаписываются с `decided_by="human_override"`. SwitchGuards уважаются даже в override.

**6. `decided_by` Literal widening** — оба типа в `src/atm/core/types.py` (lines ~334 и ~367) получают `"human_override"`. No alembic migration: DB column `String(24)`, строка длиной 14 chars.

**7. `runs.human_role`** — пишется один раз в `Runner._insert_run`: `cfg.human.role.value if cfg.human and cfg.human.enabled else None`.

### Parallelism

- **Wave 1** — Step 1: foundation (HumanCfg.extra + helper + Runner human_role). Блокирует всё остальное.
- **Wave 2** — Steps 2–6 параллельно: каждая топология — изолированный файл и тесты. Step 6 дополнительно затрагивает `core/types.py` — без конфликтов с 2–5.
- **Wave 3** — Step 7: cross-topology acceptance + codebase-map. Зависит от всех Wave 2.
