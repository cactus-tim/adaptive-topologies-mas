# m9.2 — Adaptive Role Router — План

## Краткое описание

Реализовать `HumanRoleRouter` (Protocol + Fixed/Rule/LLM-варианты) для динамической смены `HumanRole` по фазе/контексту. Расширить `HumanCfg`, прошить router в HITL-узлы 6 топологий (Chain, Star, Mesh, Debate, Hierarchical, Adaptive), добавить метрику `human_sim_cognitive_load_proxy` и колонку `runs.cognitive_load_proxy`. Обновить `runs.human_role` под динамический последний выбор через SQL-запрос к `human_interactions` при финализации run'а (Alt-A). Back-compat: при `role_router="fixed"` (default) поведение m9.1 сохраняется байт-в-байт.

## Текущее состояние

- M9.1 завершён: HITL-gateway + LLMSimulatedGateway встроены в 5 топологий; колонка `runs.human_role` пишется из `cfg.human.role` (статически).
- `HumanRole` — StrEnum (coordinator, reviewer, judge, peer, monitor); `HumanCfg` — frozen Pydantic.
- `PhaseRouter` в `src/atm/phases/manager.py` — готовый образец для нового router-слоя.
- `human_interactions.role` уже пишется callback handler'ом при каждом HITL-запросе.
- `alembic/versions/0002_human_interactions_idempotency.py` — базовая ревизия, от которой ответвляется `0003`.

## Подход

Новый модуль `src/atm/human/role_router.py` реализует:
- `HumanRoleRouter` — `@runtime_checkable Protocol` с `async def decide(phase, state) -> HumanRole`.
- `FixedRoleRouter` — возвращает константную роль (back-compat default, фабрика возвращает `None` как сигнал short-circuit).
- `RuleBasedRoleRouter` — таблица `Phase → HumanRole` (из YAML или дефолта).
- `LLMRoleRouter` — LLM + JSON parse + Pydantic + fallback на Rule при любой ошибке.

Финальная роль для `runs.human_role` берётся из `human_interactions` через SQL (`ORDER BY requested_at DESC LIMIT 1`) в `_update_run_success` — **не** через `SharedState` (Alt-A, устраняет C1).

## Риски

| Риск | Вероятность | Влияние | Митигация |
|------|-------------|---------|-----------|
| Циклический импорт `atm.core.state` ↔ `atm.human` | Низкая | Высокое | `core` независим; `SharedState` безопасно импортируется из `atm.core.state` |
| `sa.Double()` не поддерживается в SQLite-тестах | Средняя | Среднее | Используем `sa.Float()` во всей миграции и модели (фикс M6) |
| Debate `_both_judge_postprocess` closure не захватывает router | Средняя | Высокое | Явно задокументирован паттерн outer-scope capture (фикс C3) |
| Hierarchical subgraph router не пробрасывается | Средняя | Высокое | `_build_subgraph_with_human` и `_build_human_sub_reviewer_node` — оба принимают `role_router` (фикс C4) |
| FakeLLM фикстура Star не доходит до verification | Средняя | Среднее | Увеличить бюджет/iter cap в фикстуре; ≥2 разные роли — acceptance criterion |
| `human_interactions` пустой на budget-failed run | Низкая | Низкое | `scalar_one_or_none()` → None → оба поля NULL (документировано, фикс M3) |
| Phase("planning") не работает как StrEnum | Низкая | Высокое | Проверено: StrEnum.value="planning"; `Phase("planning")` корректен |

## Вне scope

- Изменение `SharedState` TypedDict (Alt-A устраняет эту необходимость).
- Интеграция router'а в `_update_run_failed` (budget-failed runs имеют NULL — документировано).
- UI/API для смены router'а на лету.
- Персистентная история ролей между run'ами.

## Открытые вопросы

1. **Веса α/β/γ** — дефолт `1.0 / 0.001 / 0.1`. Если `experiment_plan.md §5` содержит другие — заменить до финализации.
2. **`mean(context_len)` определение** — `len(json.dumps(context_json))` (байт-размер). Альтернатива: счётчик сообщений. Текущий выбор — byte-len как наиболее стабильный proxy.
3. **Phase для Mesh/Debate** — `Phase(shared.get("phase", "execution"))` / `"verification"` соответственно. RuleBasedRoleRouter вернёт фиксированную роль (без фазового разнообразия), что OK для ablation.
